# sleepvil 要件定義 v0.3

## 1. 目的とスコープ
- 目的: 毎朝ほぼ同じ時刻に、無理なく起きられる習慣をつくる。起床ミッションの達成で村が発展する
- 公開: App Store(iOS)公開を前提に開発する(アラーム機能に使うAlarmKitはiOS 26以降)
- 収益: 当面は目指さない。作る、検証する、公開することが目的
- 保存: 端末内のみ。サーバー、アカウント登録なし
- 開発は週5時間程度の個人開発

## 2. 設計の考え方(差別化と根拠)
以下は設計上の仮説で、効果は検証で確かめる。
- 評価するのは「早起き」ではなく「規則性」。睡眠を削る行動を促さないため、早すぎる起床に追加報酬は付けない
- 起床直後は認知機能が低下しているため、ミッションは「移動してスキャンする」だけにし、計算やパズルは採用しない
- 停止に使うバーコードは1つで固定する。一貫した手がかりは習慣形成に有利とされる。登録時にif-thenの文を1回だけ提示する(例: アラームが鳴ったら洗面所の歯磨き粉をスキャンする)
- 罪悪感は、上限を設けて使う(後述)。罪悪感のみで続くアプリはアンインストールで逃げられるリスクがある
- 失敗しても再開しやすい設計にする(お休みチケット、責めない文言、1回の成功で回復)

## 3. 機能要件

### MVP(アラームなし)
- F1 初回設定: 起床時刻、停止バーコードの登録(カメラ)、if-then文の表示。登録時、寝室から離れた場所の物を選ぶよう案内する
- F2 起床ミッション: アプリ内の「ミッション開始」から起動(アラーム連携は後述)。スキャンが登録値と一致したら完了。コードの種類は限定しない
- F3 ポイントと進行: 成功日数の累計を保存する(第4章)
- F4 お休みチケットとスキップ: 「今日はスキップ」を常に可能にする。チケットを消費して連続日数を保護する
- F5 村: 累計から時代と建物の段階を導出して表示する。村人が自律的に動く(第5章)
- F6 記録: 起床時刻、規則性スコア(起床時刻のばらつき)を週単位で表示する。眠気の自己評価(1〜5)は任意で記録できる

### MVP後
- F7 アラーム(AlarmKit)と連鎖再鳴動(第7章)
- F8 準備チェック(通知許可、iOSバージョン、テストアラーム)
- F9 時間帯の色合い(実時間連動)、偶発イベント
- F10 変更しやすい停止バーコードの設定画面

## 4. ポイントと進行
- 成功日数(累計): 目標時刻±15分以内の成功は1日分、それ以外の成功は0.5日分
- 連続日数: 演出専用。成長の倍率には使わない
- お休みチケット: 週1枚付与する。使用日は村の見た目の変化も出さない
- 未決: 「成功」とみなす時刻の締め切り(例: 目標時刻+60分)

## 5. 村の仕様(2D、縦画面、横スクロール)

### 時代
累計の成功日数で決まる。閾値は設定ファイルで管理する。

| 時代 | 開始(累計日数) | 長さ |
|---|---|---|
| 先史 | 0 | 60日 |
| 古代 | 60 | 55日 |
| 中世 | 115 | 55日 |
| 近世 | 170 | 50日 |
| 近代 | 220 | 50日 |
| 現代 | 270 | 50日 |
| 未来 | 320 | 45日 |

- 1時代につき建物は5段階(約10日ごとに1つ増える)
- 時代・建物の段階は累計から計算で導出する。保存しない
- 成長は後退しない。起きなかった日は成長が止まるだけ

### 村人
- 状態機械: 待機、歩行、作業、反応
- 目的地は場所のリストからランダムに選ぶ。人数は時代の進行に応じて増やす(上限は設定ファイル)
- 奥行きの表現: y座標による拡大縮小と前後の重なり、視差スクロール
- 起床ミッション完了時に、村人が集まって喜ぶ演出を入れる
- 描画: react-native-skiaで1つのキャンバスに全員を描く。30fps上限、非表示時はループを停止する
- 絵: 当面は四角形のプレースホルダー。本番はAI生成(不十分ならドット絵)

## 6. 罪悪感の設計(上限つき)
- 起きなかった日が続くと、村の見た目だけが変化する(畑がしおれる、村人が空を見上げて待つ)
- 1回の成功で元に戻る。ポイントの減少やデータ消去は行わない
- 責める文言は使わない(例: 「待ってたよ」)
- 検証の指標に「アプリを開かなくなった日数」を加え、離脱を招いていないか確認する

## 7. アラームの扱い
- MVPでは、AlarmSchedulerインターフェース(予約する、取り消す)だけを用意する
- 暫定運用: iPhone標準の時計で起き、自分でアプリを開いてスキャンする
- 将来(F7): AlarmKit(iOS 26以降)で鳴らす。停止ボタンはシステムの画面で、ミッション未完了でも止められる前提で設計する
  - 対策案: ミッション未完了なら1〜2分後に再鳴動する連鎖予約を行い、スキャン成功で残りを取り消す
  - システムのアラーム上限と、スワイプで消された場合の検知は未検証で、実機で確認する
- iOS 26未満は通常の通知にフォールバックし、確実性が下がることを明記する

## 8. UX原則
- 初期設定は3分以内
- スヌーズは標準で付けない
- どんな状況でも、アラームを止める逃げ道がある(F4)
- 失敗にペナルティの言葉を使わない
- 文字は大きく、色だけに頼らない

## 9. 非機能要件
- 信頼性(F7): 画面ロック、アプリ終了後、サイレント、省電力の4条件で鳴ること。最優先の検証項目
- 電池: 村の描画は30fps上限、非表示時は停止
- プライバシー: 通信なし、カメラ映像は保存しない

## 10. 検証計画(2週間)
- 指標: 起床成功率、起床時刻のばらつき、朝の眠気の自己評価、スキップ回数、アプリを開かなくなった日数、村を開いた回数
- 成功基準(仮): 成功率80%以上、ばらつきが開始前より縮小
- 撤退基準: アラームが不安定、または2週間で継続者が半数未満

## 11. 未決事項とリスク
- Apple Developer Programの登録が未解決。実機でのアラーム検証(開発ビルド)に必須
- 睡眠が短い日の扱い(報酬を止めるか、翌朝の目標を緩めるか)
- 成功とみなす締め切り時刻
- 絵の方針の確定(AI生成の合否判定を行い、不十分ならドット絵)
- 固定バーコード方式は、枕元に持ち込む回避が可能。検証で回避の多さを確認する
