# sleepvil ロードマップ

週5時間程度の個人開発。時間は見積りで、実測して更新する。
アラーム(AlarmKit)は検証待ちのため、MVPには含めない(要件定義の第7章を参照)。

## マイルストーン

| 段階 | 内容 | 目安 |
|---|---|---|
| M0 | Expoの初期化、Expo Goでの実機表示、READMEの最小版 | 2h |
| M1 | domain層(時代の導出、ポイント計算、規則性スコア)と単体テスト | 4〜5h |
| M2 | 保存層とストア、AlarmSchedulerの窓口(インターフェースのみ) | 3h |
| M3 | 初回設定、バーコード登録、スキャンによる起床ミッション | 6〜8h |
| M4 | 村の描画(Skia)、村人の状態機械(四角形のプレースホルダー) | 6〜8h |
| M5 | 記録画面、お休みチケット、スキップ | 4〜5h |
| M5.5 | 品質向上(画面のデザイン統一、本番の絵の判定、村の見た目) | 13h+ |
| M6 | 実機での通し確認、暫定運用(2週間)の開始 | 2〜3h |

合計の目安: 40〜47時間(約8〜10週間)。M5.5 の画像づくりの時間は含まない

## M0 の作業内容
1. `feature/m0-setup` ブランチを切る
2. Expoを `blank-typescript` テンプレートで初期化する
   - 既定テンプレートは生成コードが多く、理解できないコードを取り込まないルールに合わないため
   - リポジトリが空でない場合は、別の場所で作成して .git を除いてコピーする
3. tsconfig の `strict: true` を確認する
4. README.md を最小限(目的・状態・起動方法)で作成する
5. .gitignore に node_modules と .expo が含まれることを確認する
6. `npx expo start` を実行し、iPhoneのExpo Goで読み込めることを確認する
7. expo-camera がExpo Goで動くかを確認する(M3の前提)
8. コミットしてPRを作り、自分でレビューしてからmainにマージする

## 完了の定義(M0)
- iPhoneのExpo Goで、初期画面が表示される
- expo-camera のプレビューがExpo Goで表示できるかどうかが分かっている
- 型チェックが通る
- 上記がPRとして記録されている

## M5.5 の作業内容
運用中に見て気持ちよい品質にしてから、M6 の暫定運用に入る。
1. Q-1 画面のデザインをそろえる(4h): 色・文字・余白のテーマと共通部品を作り、4画面に使う。ノッチ対策に react-native-safe-area-context を使う
2. Q-2 本番の絵の判定(3h、画像づくりを除く): docs/ART.md に必要な絵の一覧と合格基準をまとめ、サンプルで AI 生成の合否を判定する。不十分ならドット絵(要件第5章)
3. Q-3 村の見た目を整える(6h): Skia の図形で空・背景・時代ごとの建物・村人の手足を作り込む。Q-2 の結果が出るまでは控えめにする

## 完了の定義(M5.5)
- 4画面が共通のテーマと部品で作られ、実機でノッチやホームバーに文字が重ならない
- docs/ART.md があり、本番の絵の方針(AI生成 / ドット絵)が決まっている
- 村が四角形だけでなく、時代の違いが見て分かる
- テストと型チェックが通る

## 注意
- Expo Goで動く範囲を優先する。含まれないネイティブモジュールを足す場合は、先に理由を説明する
- 実機でのアラーム検証(AlarmKit)は、開発ビルドとApple Developer Programの登録が必要
